## What Was Done
- `Makefile` with all required targets plus `help` (default), `lint-repo`,
  `lint-%`, `fmt-%` and `temporary` (lists remaining `TEMPORARY(P<step>)`
  markers, as required by `CLAUDE.md` 8.7).
- System targets (`up`, `down`, `ps`, `logs`, `build`, `build-%`, `clean`) wrap
  `docker compose` with `COMPOSE_PROFILES` defaulting to
  `core,services,frontend,observability` (`aws-local` excluded, override with
  `PROFILES=`). `up` uses `--wait` so it returns only when healthchecks pass.
- Component targets (`test-%`, `lint-%`, `fmt-%`) delegate to
  `services/<name>/Makefile` or `frontend/<name>/Makefile`; aggregate targets
  discover components by the presence of that Makefile (ADR-0002).
- Targets whose inputs are delivered later (`docker-compose.yml` → P0.3,
  `scripts/new-service.sh` → P0.4, `scripts/e2e.sh` → P1.9) fail with a
  message naming the step.
- `status` prints the "Current State" table from `docs/PROGRESS.md`, the
  `IN_PROGRESS` step row, the five latest `step/*` tags, branch and tree state,
  and `docker compose ps` when the compose file exists.

## Decisions
- ADR-0002: `build-%` goes through Compose; `test-%`, `lint-%`, `fmt-%`
  delegate to a per-component Makefile that must define `test`, `lint`, `fmt`.
- Component tests are expected to run in containers so that no language
  toolchain is required on the host; the P0.4 template enforces this.
