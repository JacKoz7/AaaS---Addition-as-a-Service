## Goal

hadolint, yamllint, shellcheck and a line-ending check. The hooks run on
commit and are also used by `make lint-repo`.

## Decisions
- ADR-0005: hook set, pinned Docker Hub hadolint instead of the upstream
  `hadolint-docker` hook (pulls `ghcr.io/...:latest`, which returned 403 from
  this network and is unpinned), commitlint rules inlined because `extends`
  cannot resolve packages from the isolated hook environment, `main`
  protected by `no-commit-to-branch`.
- The earlier override `subject-case: lower-case` was dropped: it rejected
  `start P0.5`; the config-conventional default (no sentence/start/pascal/
  upper case) is what `CLAUDE.md` 7.1 intends.

## Notes for the Next Session
- Hooks require Docker running (hadolint) and `/opt/homebrew/bin` on PATH
  (`pre-commit`). The first commit after a clone builds the hook
  environments (about a minute).
- The commitlint hook has `pass_filenames: false` and reads
  `.git/COMMIT_EDITMSG`; to lint an arbitrary file use the binary from
  `~/.cache/pre-commit/repo*/node_env-default/bin/commitlint --edit <file>`.
- Direct commits to `main` are blocked; the step-closing protocol merges with
  fast-forward, which does not trigger hooks. The P0.2 follow-up commit made
  directly on `main` would now require `--no-verify`; avoid that pattern.
- P0.6 (CI) should run `pre-commit run --all-files` and commitlint over the
  PR commit range (`commitlint --from origin/main`).
