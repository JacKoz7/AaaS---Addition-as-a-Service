## Goal
Redpanda and Redpanda Console in `compose/core.yml` (profile `core`), and a
script that creates the topics listed in `CLAUDE.md` 4.2. Result: the topics
exist after `make up`.

## What Was Done
- `contracts/events/topics.psv`: topic registry (contract) with the nine
  topics of `CLAUDE.md` 4.2: partitions (3 each), producer, consumers,
  purpose. `contracts/events/README.md` describes the directory.
- `compose/core.yml`:
  - `redpanda` (`redpandadata/redpanda:v26.2.4`): one broker in
    dev-container mode, `--smp=1 --memory=512M`; only the Kafka API
    (`redpanda:9092`) and the Admin API (`9644`) listen; the bundled HTTP
    proxy and schema registry are disabled; automatic topic creation is off;
    volume `redpanda-data`; `services` network only; health check
    `rpk cluster health`; `mem_limit: 768m` (commented deviation).
  - `redpanda-topics`: one-shot job on the broker image running
    `infra/redpanda/create-topics.sh` with the registry mounted read-only,
    after the broker is healthy; 64 MB.
  - `redpanda-console` (`redpandadata/console:v3.12.0`) on
    `127.0.0.1:8082`, Admin API enabled, networks `public` and `services`,
    health check `GET /admin/health`; starts after the topic job completes
    successfully, so `make up --wait` returns only once the topics exist.
- `infra/redpanda/create-topics.sh`: validates the registry, waits for the
  broker, creates missing topics, raises partition counts, restores
  `cleanup.policy=delete` and `retention.ms=604800000`; refuses to lower
  partitions; never deletes; `--check` verifies only.
  `infra/redpanda/README.md` documents containers, topics and operation.
- `Makefile`: `make topics` and `make topics-check` (fail with a clear
  message when the broker is not running).
- `scripts/docs-portal.py` 0.2.0: `read_topics()`; the event catalog shows
  the topic table (with the schema column filled from P1.3 on) above the
  schema table. `mkdocs.yml` watches `contracts/`.
- CI: job `compose (core)` runs `make up PROFILES=core` and
  `make topics-check`, then `make clean`; part of `ci-ok`.
- ADR-0011 (event bus); RISK_REGISTER R-010 (single broker, no replica);
  GLOSSARY: Partition, Redpanda, Topic registry; README (repository map
  gains `infra/`, `make topics-check`), ONBOARDING (Phase 1 state),
  `compose/README.md`, CODEOWNERS (`/infra/redpanda/`, `/infra/docs-portal/`).

## Verification
- `docker compose config --quiet` — valid; `COMPOSE_PROFILES=core` lists
  `redpanda`, `redpanda-console`, `redpanda-topics`.
- `make clean` then `make up` (all default profiles) — broker healthy, topic
  job exited 0, Console healthy, 15 s; `make status` shows the three
  containers.
- `make topics-check` — "9 topics match"; `rpk topic list` shows the nine
  topics with 3 partitions and 1 replica; `rpk topic describe --print-configs`
  shows `cleanup.policy=delete`, `retention.ms=604800000`.
- Idempotency — a second run of the topic job reports every topic `ok`.
- Drift — after `alter-config retention.ms=1000` on one topic and deleting
  another, `--check` exits 1 naming both; the default run restores both;
  `--check` exits 0 afterwards.
- Partitions — a registry with 4 partitions raises `aaas.dlq.v1` 3 -> 4;
  with the original registry, `--check` reports the difference and the

## Decisions
- ADR-0011: single broker in dev-container mode; HTTP proxy and bundled
  schema registry disabled; automatic topic creation off; topics declared in
  `contracts/events/topics.psv` and reconciled by a one-shot job; 3
  partitions, replication factor 1, seven days of retention; Console bound
  to the loopback interface and gated on the topic job; broker memory limit
  768 MB.
