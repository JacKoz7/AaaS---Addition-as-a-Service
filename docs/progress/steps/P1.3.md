## Goal
Event envelope and JSON Schema for `expression.submitted`,
`addition.requested`, `result.voted` and `ledger.appended` in
`contracts/events/`, plus validation of example events in CI. Result: the
first contracts.

## What Was Done
- **Schemas** (JSON Schema 2020-12, `contracts/events/`):
  - `envelope.v1.schema.json` (`$id` `urn:aaas:events:envelope:v1`): the
    closed envelope of `CLAUDE.md` 4.2 and the shared `$defs` (`uuid`,
    `uuidV7`, `timestamp`, `operand`, `sum`, `sha256`).
  - `aaas.expression.submitted.v1.schema.json`: payload `sessionId`,
    `expression` (`^[0-9+]{1,64}$`).
  - `aaas.addition.requested.v1.schema.json`: payload `a`, `b`; the
    example of `CLAUDE.md` 4.2 is one of the valid examples.
  - `aaas.result.voted.v1.schema.json`: payload `a`, `b`, `result`.
  - `aaas.ledger.appended.v1.schema.json`: payload `sequence`, `a`, `b`,
    `result`, `recordedAt`, `prevHash`, `hash`.
  - Every event schema references the envelope (`allOf`) and fixes `type`,
    `version` and `producer` with `const`; every property has a
    `description`; ownership is in `$comment`.
- **Examples**: 9 valid events and 31 invalid test cases in
  `contracts/events/examples/<topic>/{valid,invalid}/`. Envelope-level
  negative cases live with `aaas.addition.requested.v1`. Valid ledger
  examples form a real two-entry hash chain.
- **Contract test** `scripts/validate-events.py` (validate-events 0.1.0):
  meta-schema check, ADR-0013 conventions (naming, `$id`, registry and
  producer match with `topics.psv`, `const` values, envelope reference,
  property descriptions), at least one valid and one invalid example per
  event, valid examples pass and are true (`result = a + b`, ledger hash),
  invalid examples fail at their `errorAt` pointer, no example directory
  without a schema. `date-time` is asserted (`FormatChecker` with
  `rfc3339-validator`).
- **Make and CI**: `make contracts-check` (also part of `make lint`); CI
  job `contracts (event schemas)` added to the `ci-ok` needs.
- **Tool image** `infra/docs-portal` 0.2.0: pinned `jsonschema` 4.26.0 and
  its whole dependency tree.
- **Portal** `docs-portal.py` 0.3.0: the event catalog reads only
  `*.schema.json`, lists the envelope first, counts the examples and
  renders a field table per schema (`schema_fields`, `schema_constraint`);
  `table()` no longer escapes pipes inside code spans (`escape_cell`).
- **Documents**: ADR-0013; RISK_REGISTER R-011 (incompatible change inside a
  schema version); GLOSSARY (Contract test, Tolerant reader, UUIDv7,
  updated Event envelope and Hash chain); `contracts/events/README.md`;
  README and ONBOARDING (`make contracts-check`; ONBOARDING now also
  mentions the gateway from P1.2); `CLAUDE.md` 3 step 10 points to the hash
  encoding of ADR-0013.

## Decisions
- [ADR-0013](../../adr/0013-event-envelope-and-schema-conventions.md):
  dialect, URN `$id`s, file layout, envelope reuse, UUIDv7 identifiers,
  millisecond UTC timestamps, nullable `taskId` only before a task exists,
  closed schemas with tolerant consumers, payloads of the first four events,
  ledger hash encoding with a `|` separator, and the contract test.
- The contract test runs in the documentation tool image instead of a new
  image: it is a repository Python script like the portal generator.
- `addition.requested` keeps exactly the payload of `CLAUDE.md` 4.2; vote
  details (P4.5) and the idempotency key (P6.3) will be added as optional
  fields.
