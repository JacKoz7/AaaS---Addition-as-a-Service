## Goal
`parser` (OCaml, SQLite): consumes `aaas.expression.submitted.v1`, builds
the AST and publishes `aaas.addition.requested.v1` (without validator and
commutator). Result: the expression is parsed.

## What Was Done
- **Service** `services/parser` (scaffolded with
  `make new-service NAME=parser LANG=ocaml`), OCaml 4.14.2, library
  `aaas_parser` (16 modules) and the executable `src/main/main.ml`:
  - grammar `number "+" number` (lexer and parser), canonical numerals of
    any length, rejection codes with positions (`empty_expression`,
    `invalid_character`, `missing_operator`, `missing_left_operand`,
    `missing_right_operand`, `unexpected_operator`);
  - contract range guard `operand_out_of_range` (`TEMPORARY(P2.17)`);
  - tolerant decoding of `aaas.expression.submitted.v1`; production of
    `aaas.addition.requested.v1` with a UUIDv7 `eventId`, millisecond UTC
    `occurredAt`, key `taskId` and the trace continued (new span);
  - SQLite (WAL, `synchronous = FULL`) with migration runner and
    `migrations/0001_initial_schema.sql`: `ast_cache` and `processed_events`
    (idempotency by `eventId`; output stored as `pending` before publishing,
    so a retry republishes the identical event);
  - Kafka through `kafka`/`kafka_lwt` 0.5 (librdkafka 2.10): partition
    consumer of all partitions, offsets stored after processing and
    committed to group `parser`; idempotent producer, `acks=all`, 2 s
    message timeout; retries in place with backoff and jitter
    (`TEMPORARY(P3.6)`, also for rejections and discarded messages);
  - `GET /health` (`database`, `broker`, `consumer`), `GET /metrics`
    (`parser_*` counters), RFC 9457 problems for other requests, JSON logs,
    librdkafka's plain-text logging off by default (`AAAS_KAFKA_LOG_LEVEL`),
    graceful shutdown with a 9 s watchdog;
  - Dockerfile stages toolchain (pinned opam packages, no `opam update`),
    lint (ocamlformat, warnings as errors), test (Alcotest, then the JSON
    Schema check of every produced event), doc-coverage (odoc, warnings
    fatal), api-docs (odoc HTML with a module index), build, runtime
    (Alpine 3.22.2, UID 10001, 38.7 MB).
  - 60 Alcotest cases; README and all 10 documents with measured figures;
    CHANGELOG 0.1.0 via git-cliff plus Business Impact.
- **Compose**: `parser` (64m, `services` network only, volume
  `parser-data` on `/data`, depends on `redpanda` and `redpanda-topics`);
  the scaffold's database password was removed (SQLite has none).
- **Contracts** (`contract(contracts)`): the `topics.psv` description of
  `aaas.addition.requested.v1` no longer claims validation and ordering
  before P2.17.
- **Repository tooling**:
  - `scripts/validate-events.py --events FILE...` validates events produced
    by service tests against the schema of their topic (`load_schemas`
    shared with the contract check), doctests included;
  - header types: `dune-project` (preamble `(lang dune 3.20)`), `.opam` and
    `.ocamlformat` (`conf`); doc-check row `ocaml`.
- **Documents**: ADR-0015; RISK_REGISTER R-013 (single parser instance),
  R-012 extended to the parser database; GLOSSARY (AST, Idempotency
  record); ONBOARDING (watching the parser).

## Decisions
- [ADR-0015](../../adr/0015-parser-ocaml-kafka-bindings-and-sqlite.md):
  OCaml 4.14 because `kafka` 0.5 requires OCaml < 5.0; partition consumer
  as a single instance (R-013); SQLite idempotency record with the output
  stored before publishing; grammar and rejection codes; local range guard
  until P2.17; retries in place until P3.6; trace continuation with OTLP
  export left to P7.2; three health checks; documentation in `.ml` files
  checked by doc-check and odoc; contract test of the produced events.
- The executable lives in `src/main/`, not `src/bin/`: the repository
  `.gitignore` excludes `bin/` (found before the merge; the branch commits
  were rebuilt so that no commit lacks the entry point).

## Temporary Shortcuts
- `TEMPORARY(P2.17)` in `Operands.of_ast`: the operand range is checked
  locally until the parser calls the validator.
- `TEMPORARY(P3.6)` in `Consumer.process_with_retries` (retry in place
  instead of the DLQ), `Processor.reject` (rejected tasks are only
  recorded) and `Processor.handle` (undecodable messages are only logged).
