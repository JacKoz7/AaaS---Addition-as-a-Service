## Goal
`ledger` (Nim, immudb): consumes `aaas.addition.requested.v1`, calls
`successor` `b` times (`TEMPORARY(P3.3)`), stores the result with its hash
in the hash chain, and serves `GET /api/v1/tasks/{id}` (`TEMPORARY(P3.3)`,
taken over by the saga later). Result: the result is recorded.

  - consumer of `aaas.addition.requested.v1` (group `ledger`): the event and

    a 4xx marks the task `FAILED`, checkpoint every 1 000 calls;

    task status in one transaction, hash rule of ADR-0013, then
    `aaas.ledger.appended.v1` published with the acknowledgement awaited
    and recorded in `publications`; recovery republishes unpublished
    entries and resumes `COUNTING` tasks;

## Decisions
- [ADR-0017](../../adr/0017-ledger-nim-immudb-rest-and-librdkafka.md):
  Nim 2.2.12 from the official image (Alpine's 2.2.0 lacks the doc assets),
  single-threaded event loop; immudb through its REST API v1 with SQL and
  named parameters, provisioned by a one-shot container so that the service
  never holds the superadmin password; `schema_documentation` instead of
  `COMMENT ON`; idempotency by `eventId` with `taskId` as the unit of work;
  checkpoints every 1 000 calls; append lock and publication bookkeeping;
  librdkafka C API with every callback on the event loop; `TCP_NODELAY`;
  nimpretty, `nim check`, `tools/doc_coverage.nim`; immudb's Business
  Source License accepted (the last Apache-2.0 image has no arm64).
- `make up` without `--build` (CLAUDE.md 6.6).
